# 开发者教程 · 03 深入模块与贡献

> 前置：[02 架构与约定](02-架构与约定.md)。本篇是可操作的贡献手册：改哪里、怎么测、怎么发。

## 模块深潜路线

按改动频率从高到低：

1. **stores/settings.ts** —— 最常见改动：加偏好字段。改三个地方：`SettingsState` 接口、`DEFAULTS`、对应 spec。旧 localStorage 数据靠 `load()` 的 spread 合并自动补默认值。
2. **components/panels/** —— 面板 UI。图层面板（LayerPanel.vue）是复杂度担当：派生序号（items 下标+1）、视图排序（四模式 SelectButton，与拖拽互斥）、搜索过滤。新控件照抄现有 PrimeVue 用法，全局注册无需 import。
3. **components/help/** —— 关于/教程弹窗。教程数据在 `lib/help/tutorials.ts`，**与 `doc/user/*.md` 内容一一对应，改一处必须改另一处**。版本与 CHANGELOG 经 `virtual:app-info` 构建期注入（`vite.config.ts`），不要硬编码。
4. **canvas/** —— CanvasStage.vue 已满 500 行，任何新增先拆组件；交互手势在 `InteractionController.ts`（改后跑 canvas/composables 相关 spec）。
5. **src/backend/** —— Rust 侧。模型 `model.rs`、命令 `commands/`、渲染 `render/`、排版镜像 `layout/`。

## 端到端改一个功能的完整流程

以「新增一个视图开关」为例：

1. `settings.ts` 加字段 + 默认值 + spec 用例；
2. EditorView/LayerPanel 加 PrimeVue 控件绑定 `settings.<字段>`；
3. 若影响画布外观，走 `lib/canvasTheme.ts` 主题参数（亮暗两套）；
4. `pnpm check && pnpm test`；
5. `CHANGELOG.md` `[Unreleased]` 加条目；
6. 提交（中文 commit message，与现有风格一致）。

## 新增 Rust 命令 checklist

- [ ] `commands/` 新文件 + `lib.rs` 注册到 `invoke_handler`
- [ ] `capabilities/default.json`（或相应文件）声明权限
- [ ] 前端封装层（参照 `composables/useProjectFile.ts` 的 invoke 用法）
- [ ] 纯逻辑抽纯函数并配 `#[cfg(test)]`；跨边界行为配 `src/backend/tests/` 集成测试
- [ ] 若改动文档结构 → 停下，回到 02 篇契约红线评估兼容性

## 发版流程

1. 把 `CHANGELOG.md` 的 `[Unreleased]` 收口为新版本节（Keep a Changelog 中文格式）；
2. 同步三处版本号：根 `package.json`、`src/backend/tauri.conf.json`、`src/backend/Cargo.toml`（`.github/workflows/release.yml` 会校验 tag 与这三处一致）；
3. 本地跑 `pnpm check && pnpm test`；
4. 打 annotated tag `vX.Y.Z` 并推送，CI 自动构建 Linux（deb/appimage）与 Windows（nsis）安装包、创建 Release；`-beta.N`/`-test.N` 后缀会被识别为预发布；
5. 首次发版或改了 workflow 时，先用 `v*-test.1` 标签验证整条链路再正式发。

## PR / 提交规范

- 一个提交只做一件事；commit message 用中文、祈使句、带类型前缀（`feat:` / `fix:` / `test:` / `docs:` / `refactor:`），与 `git log` 现有风格一致；
- PR 描述里写清：动机、改动点、验证方式（check/test 结果截图或摘录）；
- 不通过降低门禁、跳测试、删负向测试文件的方式让 CI 变绿。
