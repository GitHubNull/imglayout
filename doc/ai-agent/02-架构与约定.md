# AI 代理教程 · 02 架构与约定

> 前置：[01 快速上手](01-快速上手.md)。本篇解释系统结构与不可违反的约定及其原因。

## 前端模块分层

```
views/        编排层：EditorView 组装一切，不承载业务逻辑
components/   UI 层：只展示与转发事件，业务状态全部来自 store/composable
stores/       Pinia 单一流：project.doc 是唯一事实来源
composables/  画布视图/舞台缩放/项目文件/全局快捷键
lib/          纯函数：无副作用，全部可单测
types/        与 Rust serde 契约对应的类型
```

数据流单向：组件 → store action → `doc` 变更 → computed 回填 UI。组件不持有文档副本。

## 前后端契约边界

`src/frontend/src/types/layout.ts` 的 `LayoutDoc`/`PhotoItem` 与 `src/backend/src/model.rs` 的 serde（camelCase）**一一对应**，`.imglayout` 项目包就是这个结构的 YAML 序列化。后果：

- **禁止给这些结构加字段**——单方面加字段会被另一端 serde 拒绝或静默丢失；
- 一切显示用派生量（如图层面板的序号 = items 数组下标 + 1）必须在 computed 里算，不落盘；
- 图层次序语义：items 数组**末尾 = 最顶层**（PS 口径），任何排序视图都不能改这个数组来表达。

## 撤销栈约定

`project.snapshot()` 深拷贝 `doc` 入撤销栈；**所有修改前先快照**。store 内的 `reorder`/`moveItem`/`updateItem` 等已内置或要求外部先快照（看现有调用方式照抄）。连续手势（不透明度滑杆）在手势起点记一次快照、过程内合并。

## 门禁与行数

- `pnpm check` 四步全绿才算过：Rust 侧 `clippy -D warnings` + `fmt --check`，前端侧 `vue-tsc -b --noEmit` + `vite build`。**存量也是零告警**，新增告警直接失败。
- 单文件 ≤500 行硬上限。逼近时按「组件抽子组件 / store 抽纯函数到 lib」拆分。

## 测试布局

- 前端 vitest：spec 与被测文件**同目录**同 stem；PrimeVue 组件测试用 `@vue/test-utils` mount + 手动注册用到的 PrimeVue 子组件；Dialog 内容 Teleport 到 body，用例间务必 unmount 防串扰（见 `components/help/*.spec.ts` 的 afterEach 范式）。
- Rust：`#[cfg(test)]` 内联 + `src/backend/tests/` 集成测试（如 `export_engine.rs`）。

## 文案与内容约定

- 无 i18n：UI 文案中文硬编码。
- primeicons 8 删了 `pi-redo` 等字形（用 `pi-refresh`），新增图标先验证字形存在。
- `src/frontend/src/lib/help/tutorials.ts`（软件内教程数据）与 `doc/user/*.md` 一一对应，改一处必须改另一处。
- 版本号单一来源：根 `package.json`；前端经 `virtual:app-info`（`vite.config.ts` 里的插件）构建期注入 `APP_VERSION`/`APP_CHANGELOG`，不要在前端硬编码版本。
