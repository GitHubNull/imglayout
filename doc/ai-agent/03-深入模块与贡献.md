# AI 代理教程 · 03 深入模块与贡献

> 前置：[02 架构与约定](02-架构与约定.md)。本篇讲关键模块的深坑与改代码的标准流程。

## 画布与交互栈

```
CanvasStage.vue（500 行上限已满，勿再加）
├─ InteractionController.ts   鼠标/触摸手势状态机：选择、拖动、旋转、缩放、框选
├─ GuidesController.ts        参考线：从标尺拖出、命中、移动、锁定
└─ drawGuides.ts / lib/canvasTheme.ts   绘制与亮暗双套调色板
```

- 画布主题已参数化：`lib/canvasTheme.ts` 按 `settings.theme` 出参数，新增绘制元素必须走主题变量，禁止硬编码颜色。
- 修改 InteractionController 后，相关 spec 必须同步（前端测试怪癖：合成拖拽 `up` 必带末坐标、1px 线全像素扫描，见 composables 与 canvas 目录下的 spec）。
- 缩放/自适应逻辑在 `ZoomControls.vue` + `useStageResize.ts`：resize 重 fit、缩放不跳回 100%。

## 导出与排版算法

- 排版算法是纯函数：`lib/layout/{grid,masonry,free,align}.ts`，前端可测；`src/backend/src/layout/` 是 Rust 镜像，**两边有对拍测试**（`lib/layout/layout.spec.ts`）——改算法必须两端同步改，对拍用例保持绿。
- 导出渲染在 Rust `src/backend/src/render/`：照片解码、按 rect/DPI 合成、JPEG/PNG 编码。集成测试 `src/backend/tests/export_engine.rs`。

## 项目包（.imglayout）

实现：`src/backend/src/commands/package.rs`；规范：`doc/layout-schema.md`。

- zip（deflate）内 `layout.yaml` + `assets/<assetId>.<扩展名>` 原图；
- 加载解到 `appdata/packages/<包名>/`，有 zip-slip 防护；
- `version` 字段是**文件格式版本**（当前恒 1），不是应用版本；
- 旧 JSON 格式（`commands/project.rs` 的 `ProjectFile`）仍兼容，别删。

## 典型改造任务

**新增一个设置项**（例：`layerIndexVisible`）：
1. `stores/settings.ts`：`SettingsState` + `DEFAULTS` 加字段（旧 localStorage 自动补默认）；
2. UI 组件绑定 `settings.<字段>`，EditorView 的 `$subscribe` 自动持久化，无需手写；
3. `settings.spec.ts` 补默认值/合并用例。

**新增一个弹窗**：仿 `components/help/AboutDialog.vue`——`defineModel<boolean>` + PrimeVue Dialog；EditorView 加 `ref` 与顶栏按钮；`components/help/*.spec.ts` 范式写测试（注意 Dialog Teleport 与 unmount 清理）。

**新增一个 Rust 命令**：
1. `src/backend/src/commands/` 实现，`lib.rs` 注册 `invoke_handler`；
2. `capabilities/` 加权限；
3. 前端封装 invoke（参照 `composables/useProjectFile.ts`）；
4. 涉及文档结构时——回到 02 篇的契约红线。

## 发版流程（不要自行打 tag）

1. 所有变更在 CHANGELOG `[Unreleased]` 累积；
2. 发版时把三处版本号（根 `package.json`、`src/backend/tauri.conf.json`、`src/backend/Cargo.toml`）改为新版本，CHANGELOG 收口出新版本节；
3. 推 `vX.Y.Z` tag 触发 `.github/workflows/release.yml`（CI 会校验 tag 与三处版本一致，不一致即失败）；
4. CI 产出 deb/appimage（Linux）与 nsis（Windows）并建 Release。

## 改代码的标准流程

1. 读懂现有实现（spec 是最好的用法文档）；
2. 改代码 + 补/改 spec；
3. `pnpm check && pnpm test`；
4. CHANGELOG `[Unreleased]` 加条目；
5. 提交。**不要**顺手重构无关代码、不要放宽门禁、不要删「看起来没用」的负向测试文件。
